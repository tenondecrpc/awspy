# Documentation standards

- Describe implemented behavior as implemented and future behavior as proposed.
- Keep mutable state in `docs/status/`; keep accepted ADRs immutable and supersede them with a new ADR.
- Use stable work-item and finding IDs.
- Include evidence, affected scope, acceptance criteria, tests, dependencies, blockers, and validation for actionable work.
- Mark external facts `NOT VERIFIED` when authoritative verification is unavailable.
- Use Mermaid only when it clarifies relationships or flow.
- Keep commands exact and label commands that were not executed.
